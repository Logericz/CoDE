# Guarded：首次实际方法修改及十题缓存筛查

日期：2026-10-09。新候选已实现并接入共享控制器、有界单题CLI。
本轮新增了实际调度行为；未运行新GPU请求，下面均为已有轨迹的事后开发回放。
设计基于已暴露的十题，不能当作独立验证或方法新颖性证据。

## 1. 改动及阅读入口

先读 [guarded.py](../src/online_methods/guarded.py)，完整思路见
[设计说明](../docs/GUARDED_SCHEDULER.md)。关键变化：

```diff
- 原Adaptive：incomplete probe一律h=1；信号间隔与成本间隔取min
+ Guarded：valid incomplete可进入风险判断；低风险h=2，其余h=1
```

数值无效、有效历史少于3次、信号缺失、计时异常、置信下降仍恢复逐点探测。
对其余状态，计算距置信/D停止边界的余量m及近期变化率u；只有
`m>0.05`且`2u<m-0.05`时跳过一个候选。该局部预测不保证未来信号平稳。
共同D计算、停止判断、主生成、probe和最终补答都不改，旧Adaptive保持作对照。

单题CLI新名称为`codestop-guarded`；原默认三配置、十题批处理的四配置清单保持
原样。源码哈希清单已加入新模块，旧GPU gate继续拒绝当前新源码。
`h_max`与`beta`不参与该候选，保护带复用`margin_m0`；首次回放固定0.05。

本轮同时改变incomplete调度分支与成本min，不能把结果单归因于其中一处。
若将此思路发展成正式方法，须增加分别恢复两个限制的消融，不能直接命名为
已证实的创新方法。

## 3. 为什么dev06会改变

dev06在第4次查询后，当前置信度约0.83594，D约1.17070，得到m约0.11406、
u=0.0078125。`2u=0.015625 < m-0.05≈0.06406`，于是下次在j6查询，跳过j5。
j6的probe满足原置信停止规则，仍与Dense在同一位置停止。

保护在另外两题发挥了作用：dev07的j3出现D快速增长，仍在j4查询并停止；
dev09的j3虽是未完成probe，但置信度已很高、m=0，保留j4的检查机会。
这些例子只解释这次规则运行，不能说明它在新题上也不会漏掉停止机会。

十题Guarded均能找到同停止位置、同原因、同主轨迹前缀的旧答案路径；回放脚本
未复制答案或判分。这不能代替新策略GPU输出和质量验证。Fixed-h2的dev07停止
位置是新端点，没有旧补答，答案质量保持未知。

## 4. 验证、范围与下一次修改

- 94项定向测试通过：Guarded规则12、共享引擎/协议/旧方法/身份56、单题CLI19、
  因果回放7。没有重跑完整仓库测试。
- 单独运行CLI测试时暴露了测试文件缺少scripts导入路径的问题，已补显式路径后
  19项通过；没有调整生产算法来绕过失败。
- 真实缓存357项检查通过；59个归档输入与18个当前设计/源码文件前后hash一致。
- 原始实验、判分、冻结数据、学习注释和稿件均未修改。
- 本轮新增GPU请求0；当前方法的GPU数值/时延验收仍待执行。

第一版已经实现实际稀疏，当前收益规模仍不足以支持扩量。本轮保留固定规则与
全部结果，不在这十题上继续网格调参。

下一次方法修改优先考虑：用主推理中已经可见的低成本信号改善“停止机会风险”
判断，并与简单规则比较；候选间隔与token间隔结合可以作为额外约束，主要用于
减少长跨度跳过风险，不能预设它会增加收益。自适应probe长度另列，因为它改变
观测本身，现有21-token缓存不能评价追加生成的试答。

是否进行少量GPU验证，需要结合后续候选的收益空间判断；当前不启动四卡主矩阵。
最初方案中单位评分与无warm-up机制诊断仍是待办，但不再作为所有方法修改的
先决条件。设计、实现、缓存筛查与GPU验证分别报告。
